# acpc a2a: an ACP agent served over A2A

2026-11-17

`acpc a2a --listen ADDR [--cwd DIR] [-c FILE] [--card FILE] [--ask] -- CMD`
serves one ACP agent as an A2A v1.0 server (JSON-RPC binding, streaming),
with github.com/a2aproject/a2a-go/v2 v2.8.0 for the protocol.

## Why acpc

The bridge has to understand ACP (turns, stop reasons, permission
requests), which acphost does not: it proxies and journals frames. acpc is
already the ACP client on top of acphost, with durable named sessions and a
prompt queue, so an A2A context maps onto what exists. Agents need no A2A
code; towa, jcode and claude-agent-acp work the same.

## Mapping

- A context is a session named `a2a-<16 hex of sha256(contextId)>` in the
  sessions root of `--cwd`. The client picks the context id, so it is
  hashed into a safe path element. A new context runs `Create`, an
  existing one `Reach`, so a stopped host restarts and loads the
  conversation as for `acpc prompt`.
- A task is one turn, queued with `Enqueue`/`OpenQueued` like `acpc
  prompt`: two tasks in one context run in order, and an `acpc prompt` on
  that session waits its turn too.
- Text, URL and data parts become the prompt text; raw parts become files
  (`acpc.Attachment`) with the part's media type.
- The agent's message chunks stream as one artifact (first event creates
  it, the rest append). A tool call's title, each time it changes, is a
  working status message. Stop reasons: `end_turn` completed, `cancelled`
  canceled, `refusal` rejected, others failed with the reason; an error
  (host gone, agent failed to start) fails the task with the error text.
- Cancel sends `session/cancel` through the session's interrupt channel
  (`Options.Interrupts`, which replaces the process signals the CLI uses),
  and the turn's stop reason ends the task.

## Permissions

`--approve-reads` (default), `--approve-all` and `--deny-all` work as for
`prompt`. `--ask` sets `Options.Ask`: the ACP permission request stays
pending while the task is at `input-required` with a message listing the
options; a message on that task naming an option id or name answers it,
anything else asks again. Cancel at `input-required` answers the request
as cancelled and the turn ends canceled.

a2a-go stops an execution at `input-required` and starts a new `Execute`
for the reply, while the ACP request has to stay open. So each task has a
goroutine that owns its acpc session for the whole turn and sends events
on a channel; `Execute` relays them and returns at `input-required`, and
the next `Execute` for the task passes the reply and relays the rest.

## Security

It listens only on a loopback address or `unix:PATH`, and has no
authentication of its own (user, 2026-11-17): stronger auth is a proxy in
front. The card file is merged into the agent card so it can name the
proxy's URL (`supportedInterfaces`) and auth (`securitySchemes`,
`securityRequirements`). A unix socket has no URL, so it needs
`supportedInterfaces` in the card.

## Limits

- Task state is a2a-go's in-memory store: after an `acpc a2a` restart,
  earlier task ids are unknown, though contexts keep their sessions and
  conversations. A turn running at the restart keeps running in its host.
- Only the JSON-RPC binding is served; the REST and gRPC ones would add
  a route and protobuf, respectively.

## Checks

- `go test -race ./cmd/acpc -run TestA2A`: the fake agent behind a real
  host, through the a2a-go client: a context keeps its agent session,
  another context gets its own, `--ask` round trip with a bad reply,
  cancel at `input-required`, cancel of a running turn, then the session
  still answers. Non-loopback `--listen` addresses are refused.
- Live, 2026-11-17, towa (`session.mode: ask`) with claude-haiku-4-5:
  a file read streamed "pelican"; a later task in the same context
  recalled it with no tools; another context did not know it; a bash
  call stopped at `input-required` with towa's three options and ran
  after `allow_once`. acpc a2a RSS was 22 MB.
- Binary (`go build`, unstripped): 16.4 MB at the commit before, 18.9 MB
  with a2a-go. No gRPC or protobuf module is linked.
