# ACP v2 (experimental)

2026-11-16. `acpc new --protocol 2` and `acpc exec --protocol 2` speak the
ACP v2 draft (go-acp's `v2` package). The flag is hidden and version 1
stays the default. The draft can change in any release, and so can this.

- The version is stored in `client.json` (`protocol`) when the session is
  created, so later `prompt`, `attach` and `cancel` use it. A cached
  initialize result from the host wins over both.
- An agent that answers a v2 initialize with another version is an error.
  acpc does not fall back to v1, so a v2 test never runs as v1 by mistake.
- The prompt result in v2 only acknowledges the prompt. The turn ends when
  the host sends `turn_end` for the agent's idle `state_update` (acphost
  0.29, `docs/notes/2026-11-16-acp-v2-turns.md` there). Cancel, `--no-wait`
  and the exit status work as in v1 on top of that.
- A restarted agent reopens the session with `session/resume`, which is
  baseline in v2, in place of `session/load`.
- Prompt content is built with the v1 types and converted to v2 through
  JSON: text, image, resource and resource link blocks have the same wire
  form in both.
- `pkg/acpc/protocol.go` holds the per-version calls behind one interface.
  Session logic is shared.
- Not done: v2's upsert-style updates (`agent_message`, `TerminalUpdate`,
  `plan_update`) are not rendered. Only chunks, tool calls and the turn end
  show.
