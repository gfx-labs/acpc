# 165: cmd/acphost CLI

2026-11-06

`acphost` runs acphost by hand, to debug sandboxing and isolation without
jobshop.

```
acphost run  -c FILE [--dir DIR] [flags] -- CMD ARGS...
acphost host -c FILE --dir SESSIONDIR [--lease 30m] [flags] -- CMD ARGS...
```

- `run` starts one command with `proc.Start`, stdin/stdout/stderr passed
  through, and exits with its status (128+n for a signal, 125 for a
  setup failure such as a bad bwrap mount, 2 for a usage or config
  error). No ACP, socket, journal or lease. `--dir` is the working dir
  (default: cwd).
- `host` writes `spec.json` into SESSIONDIR and runs `acphost.Main` in
  the foreground, as jobshop spawns it. The agent runs in the cwd; the
  session name is SESSIONDIR's base name. It prints the socket path.

Flags: `-c FILE` (`-` reads stdin; then the command gets no stdin),
`--network host|none|pasta`, `--ro SRC[:DST]`, `--rw SRC[:DST]`,
`--join TYPE=PATH` (repeatable), `--print` (bwrap/pasta argv, newuidmap
lines, join plan; runs nothing), `--check` (CheckSpawn and Preflight,
with mode and owner of each path in a spawn failure), `-v` (isolation
record to stderr after the run).

## Config

YAML (JSON works too). One object: `sandbox`, `user`, `cgroup`, `env`,
`join`. The keys are acphost's JSON keys, the same ones jobshop's
`sandbox:` and `isolation:` sections use, so a section pastes over.
Unknown keys are an error. The YAML is converted to JSON and decoded
with unknown fields refused, so `Mount` keeps its string-or-object form.
A mount object is decoded by `Mount`'s own unmarshaler, so an unknown
key inside one is not caught; a mount without `src` is.

Minimal, no network:

```yaml
sandbox:
  ro: [/nix, /etc]
  rw: [/home/me/work]
  hide: [/home/me/work/.secrets]
  network: none
  env_keep: [PATH, HOME]
```

pasta with DNS and a deny list:

```yaml
sandbox:
  ro: [/nix, /etc]
  rw: [/home/me/work]
  network: pasta
  deny: [10.0.0.0/8, 192.168.0.0/16]
  dns: {forward: 169.254.1.1, host: 127.0.0.53}
  resolv_conf: /etc/acphost/resolv.conf
  env_keep: [PATH]
```

Mapped user and a cgroup:

```yaml
sandbox:
  ro: [/nix, /etc]
  rw: [/home/me/work]
user: {uid: 1000, gid: 1000, map_uid: 100000, map_gid: 100000, map_count: 65536}
cgroup: {parent: /sys/fs/cgroup/user.slice/user-1000.slice/user@1000.service/acphost, memory_max: 2G, pids_max: 512}
env: [LANG=C.UTF-8]
```

## Dependency

`go.yaml.in/yaml/v3` moves from indirect (via testify) to direct, for
the config file. It was already in go.sum; no new module.
